# Charliej from WIUT: setup guide (personal codes, requests, admin panel)

## What is in this folder
- `public/index.html`: sign-in page (student ID + personal code) and the "Request access" form. It holds no study material.
- `public/admin.html`: administrator panel (works on a phone).
- `netlify/functions/*`: the server programs (sign-in, access requests, serving the study site only to signed-in students, activity log, admin).
- `netlify/lib/app-html.mjs`: the study site itself, kept on the server.
- `netlify.toml`, `package.json`: Netlify settings. Do not edit.

## Deploy (GitHub method, about 10 minutes)
1. Create a free account at github.com and a **private** repository (for example `charliej-qm`).
2. Unzip this package. In the repository choose **Add file, Upload files**, drag in everything from the unzipped folder (keep the folders), then **Commit changes**.
3. Go to app.netlify.com, **Add new site, Import an existing project**, choose GitHub and your repository. Netlify reads `netlify.toml`. Click **Deploy**.
4. In Netlify open **Site configuration, Environment variables** and add these variables (values are in the chat message; never put them in GitHub). The first two are required, the Telegram ones are optional:
   - `TOKEN_SECRET`
   - `ADMIN_HASH`
   (`STUDENT_CODE` is no longer used. Each student now has a personal code.)
5. **Deploys, Trigger deploy, Clear cache and deploy site**. Wait until it says Published.
6. Open `your-site.netlify.app/admin.html`, sign in, and add your first student.

Netlify CLI alternative: `npm i -g netlify-cli`, `netlify login`, `netlify link`, set the variables, `netlify deploy --prod`.
(Dragging the folder onto Netlify Drop may not install the storage package the functions need, so use GitHub or the CLI.)

## Updating a site that is already online
1. Unzip the new `charliej-netlify.zip`.
2. On GitHub open your repository, choose **Add file, Upload files**, drag in everything from the unzipped folder (keep the folders), and **Commit changes**. Same-named files are replaced.
3. Netlify notices the change and publishes it by itself in about a minute. Your passwords, student list and activity log are NOT touched.

## How students get access
**Way 1, you create them (works from a phone):** admin panel, **Add students**. Type name, ID, group (or paste a whole list, one per line: `Full name, Student ID, Group`). Each student gets a personal code, shown once, with WhatsApp / Telegram / Copy buttons to send it privately.

**Way 2, they request (also from a phone):** the student opens the site, taps **Request access**, enters name, student ID, group and a Telegram/phone contact. You see it under **Requests**, check it is really your classmate, and tap **Approve**. The student presses **Check again** on the same device and their personal code appears once. You also get the code on your screen if you prefer to send it yourself.

Rules the site enforces: one registration per student ID; a second request for an ID that is waiting or registered is refused; at most 5 requests per connection per day; codes are generated by the site (nobody can pick or edit one); the site stores only a one-way hash of each code.

## Get a phone alert for every new request (Telegram, free, 5 minutes)
You do not need to keep the site open. With this, Telegram sends you a message the moment someone requests access, with a button that opens the admin panel so you can tap Approve.
1. In Telegram, open **@BotFather**, send `/newbot`, choose a name and a username. It gives you a **token** that looks like `123456789:AAF...`.
2. Open your new bot in Telegram and press **Start** (send it any message).
3. To find your chat number, open @userinfobot, press Start; it replies with your **Id** (a number).
4. In Netlify add two more environment variables and redeploy:
   - `TELEGRAM_BOT_TOKEN` = the token from step 1
   - `TELEGRAM_CHAT_ID` = your Id from step 3
5. Test: open the site in a private window, send yourself a request. The message should arrive within seconds.
Alerts you will receive: a new access request, a successful administrator sign-in (so you notice if someone else gets in), and a lock-out after 5 wrong administrator passwords. If the variables are missing, the site simply works without alerts. Keep the bot token secret like the other values.

## Daily use
- **Requests** tab: approve or reject. **Students** tab: last seen, sign-ins, tests finished/started, average score, time on site, number of different IP addresses (a warning appears from 4), **Revoke** / **Restore** / **Reset code**. **Activity** tab: every action with Tashkent time, plus CSV export.
- Lost code: **Reset code**, then send the new one. The old code stops working at once.
- Sign everyone out immediately: change `TOKEN_SECRET` and redeploy.

## What the protection can and cannot do
Can: keep the material private from anyone without a personal code; tie every action to a registered student; cut off one student instantly; lock a connection after repeated wrong guesses (10 for students, 5 for admin); keep the admin password out of the code.
Cannot: prove that the person who requested access is who they claim (you decide when you approve); stop a student from handing over their code or saving pages. The IP-address warning and the activity log help you notice sharing.
